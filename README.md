# FL Pack 1.2.2

Windows-утилита: папка с проектами → штатный Zipped loop package FL Studio → проверка ZIP → удаление папки проекта. React, shadcn/ui, Electron.

## Запуск

Готовая Windows-сборка: [скачать FL Pack 1.2.2](https://github.com/lilstarcollex/FruityBatch/releases/download/v1.2.2/FL-Pack-1.2.2-Windows.exe). Все версии доступны в [Releases](https://github.com/lilstarcollex/FruityBatch/releases).

Откройте `release/FL-Pack-1.2.2-Windows.exe`. Перед обновлением закройте старое окно утилиты. Node.js и Python для готовой сборки не нужны. FL Studio должна быть установлена и закрыта перед запуском очереди.

Выберите папку, нажмите «Запустить» и «Начать». Проекты обрабатываются последовательно. Результат — `<имя папки проекта>.zip` рядом с исходной папкой.

## Обработка

- Поиск рекурсивный. Проект определяется одним FLP в корне своей папки. Backup и служебные папки не участвуют в поиске. При нескольких основных FLP утилита сообщает об ошибке.
- Приоритет у установленной FL Studio 2025; если версия FLP требует более новой установленной версии, используется 2026.
- Экспорт выполняет FL Studio через штатный `/Z<путь к FLP>`. Утилита **не создаёт ZIP, не пересобирает его, не пережимает, не заменяет FLP и не добавляет файлы**.
- Проверка полностью читает записи ZIP, сверяет CRC32 и размеры, проверяет безопасные имена и контейнер FLP. Требуется один FLP в корне с ожидаемым именем. Аудио не декодируется; сравнение музыкального содержимого с исходником не выполняется.
- Внешний SHA-256 архива записывается в служебный журнал для восстановления. Итоговый файл содержит те же байты, которые создала FL Studio.
- Перед удалением проверяется, что исходники не изменились во время экспорта, а проверенный ZIP не подменён. Публикация без перезаписи существующего результата; удаление через служебный карантин с восстановлением после сбоя.
- Файлы анализа `<существующий WAV>.zpa` и временный `<имя FLP>.zip~`, созданный экспортёром, учитываются отдельно: их создание и обновление не блокируют повторный запуск. FLP, аудио и остальные исходники по-прежнему проверяются; перед удалением фиксируется и сверяется полный актуальный состав папки. При временной блокировке переименование в карантин повторяется до 5 раз в течение 3 секунд.
- Блокирующие диалоги FL Studio и её дочерних процессов автоматически подтверждаются или закрываются. Обработка не переключает фокус на FL. Предупреждение записывается в служебный журнал `.flpack`; в ZIP ничего не добавляется. Таймаут экспорта — 2 минуты на проект. Если окно не удалось закрыть или экспорт не завершился вовремя, исходная папка сохраняется, очередь переходит к следующему проекту.

**После успешной проверки папка удаляется целиком, включая Backup и неиспользуемые файлы. В ZIP остаётся только то, что включила сама FL Studio.** Проверка целостности не подтверждает наличие плагинов или идентичное звучание проекта.

## Старые результаты

Архивы 1.0/1.1 автоматически не исправляются и не перезаписываются. Продолжение удаления по старым журналам заблокировано. Для новой обработки нужны исходные папки и свободные имена результатов. Старые архивы могут содержать исходные файлы в `__flpack__/source/`; исходные пути перечислены в manifest. Не удаляйте их до восстановления нужных проектов.

## Разработка

`npm install`, `npm run build`, `npm test`, `npm run test:dialogs`, `npm run test:ui`.

`npm run test:real` проверяет реальный экспорт на свежих копиях материалов «для теста». `node scripts/test-regression.mjs` проверяет копии «МИГ» и Kontakt mix из сохранённых исторических тестовых архивов. Тесты сравнивают SHA-256 всего ZIP сразу после штатного экспорта и после публикации. `node scripts/test-packaged.mjs --regression` запускает собранное приложение на копиях. Отчёты сохраняются в `test-results`.

`npm run dist` собирает автономный EXE с экспортёром pywinauto. ZIP читает yauzl; записывающих ZIP-библиотек в runtime нет. yazl используется только для тестовых фикстур.
